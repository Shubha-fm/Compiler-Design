# Compiler Design Programs 291–295

Five new standalone C11 educational examples, numbered after the existing 290 compiler programs.

| No. | Source | Topic |
|---|---|---|
| 291 | `291_lexer_token_positions.c` | Token scanning with one-based byte-column diagnostics |
| 292 | `292_postfix_regex_nullable.c` | Evaluate postfix regex nullability using a stack |
| 293 | `293_grammar_unit_closure.c` | Transitive closure of CFG unit productions |
| 294 | `294_cfg_immediate_dominators.c` | Immediate dominators in a reachable single-entry CFG |
| 295 | `295_postfix_stack_codegen.c` | Stack-machine instruction generation from postfix expressions |

## Run sample checks

```bash
bash tests/test_programs_291_295.sh
```

## Compile an example

```bash
gcc -std=c11 -Wall -Wextra -pedantic programs/295_postfix_stack_codegen.c -o stack_codegen
echo 'ab+c*' | ./stack_codegen
```

The source programs are educational, bounded examples. The lexer uses ASCII-like identifiers and one input line, and reports byte columns. The postfix regex uses `#` for epsilon, `.` for concatenation, `|` for alternation, and `*` for Kleene star; it computes only the nullable predicate, not a complete matcher. The unit-production example reports reachability, rather than rewriting all grammar rules. The CFG immediate dominator example requires every block to be reachable from block 0. Postfix code generation uses one-character operands, without constant folding or source-level type checking.

The sample script compiles each program and performs ten checks. Run it manually. The removed C/C++ CI workflow has not been restored.
