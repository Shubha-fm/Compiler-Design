# Compiler Design C programs 306–310

Five independent C11 examples advancing from token recognition to parser and program analysis.

| No. | Program | Core topic |
|---|---|---|
| 306 | [Trie keyword lookup](306_trie_keyword_lookup.c) | Keyword recognition using a lowercase trie |
| 307 | [Regular-expression derivatives](307_regex_brzozowski_derivative.c) | Residual-state matching of the fixed regular language `a*b` |
| 308 | [Basic-block CFG edges](308_cfg_basic_block_edges.c) | Leaders and edges for branches and jumps |
| 309 | [Dead-store elimination](309_ir_dead_store_elimination.c) | Backward liveness in straight-line assignments |
| 310 | [LR(0) item closure](310_lr0_item_closure.c) | Closure over nonterminal symbols following the item dot |

## Build and run

```bash
bash tests/test_programs_306_310.sh

gcc -std=c11 -Wall -Wextra -pedantic programs/310_lr0_item_closure.c -o lr0
printf '3\nS AB\nA a\nB b\n0\n' | ./lr0
```

These educational programs intentionally have small input models. Program 306 uses lowercase ASCII keyword names. Program 307 is a worked derivative-state recognizer for only `a*b`, not a general regex engine. Program 308 supports NORMAL, BR, JMP and HALT instructions. Program 309 assumes side-effect-free SET instructions and no branches. Program 310 uses single-letter symbols and omits epsilon productions. The sample checks are representative, not exhaustive.

The C/C++ CI workflow stays removed.
