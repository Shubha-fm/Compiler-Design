# Programs 261–270: Compiler Design in C

Ten standalone C11 educational programs.

| No. | Program | Concept |
|---|---|---|
| 261 | `261_lexer_integer_underscore.c` | Validate digit separators in decimal integer tokens |
| 262 | `262_dfa_complement_acceptance.c` | Run complement of a binary DFA |
| 263 | `263_cfg_reachability_pairs.c` | Count ordered reachable CFG vertex pairs |
| 264 | `264_grammar_epsilon_removal_variants.c` | Enumerate nullable RHS variants |
| 265 | `265_parse_table_cell_count.c` | Count predictive parse-table cells and check conflicts |
| 266 | `266_dataflow_very_busy_expressions.c` | Backward must-analysis of very-busy expressions |
| 267 | `267_ir_three_address_to_triples.c` | Convert restricted TAC instructions to triples |
| 268 | `268_linear_scan_register_allocation.c` | Simple interval-based register allocation |
| 269 | `269_peephole_redundant_moves.c` | Remove self-copies and immediate duplicate moves |
| 270 | `270_lr_parse_action_decoder.c` | Decode shift, reduce, accept and error actions |

## Compile and test

```bash
bash tests/test_programs_261_270.sh
gcc -std=c11 -Wall -Wextra -pedantic programs/270_lr_parse_action_decoder.c -o lr_action
echo r12 | ./lr_action
```

**Scope:** These are small teaching examples, not production compiler passes. Program 262 requires a complete DFA. Program 264 limits the production length to 12 characters. Program 266 expects the user to supply GEN/KILL masks. Program 267 assumes straight-line three-address assignments; it does not perform full dependence or value-numbering analysis. Program 268 expects intervals in start-order and does not guarantee optimal spilling. Program 269 demonstrates limited peephole transformations under simplified semantics. Sample tests cover one representative case per program and are not exhaustive. C/C++ CI remains removed.
