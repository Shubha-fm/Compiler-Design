# Compiler Design C Programs 271–280

Ten standalone C11 teaching exercises.

| No. | Program | Topic |
|---|---|---|
| 271 | `271_lexer_floating_literal.c` | Simplified decimal floating-point literal recognition |
| 272 | `272_dfa_unreachable_pruning.c` | Reachable-state pruning for a binary DFA |
| 273 | `273_grammar_first_terminals.c` | FIRST terminal sets for grammars without nullable productions |
| 274 | `274_lr_stack_action_simulator.c` | Educational shift/reduce stack simulation |
| 275 | `275_cfg_loop_header_candidates.c` | DFS back-edge loop-header candidates |
| 276 | `276_dataflow_gen_kill_transfer.c` | GEN/KILL bit-vector transfer |
| 277 | `277_ir_dag_expression_sharing.c` | Counting reusable pure expressions |
| 278 | `278_register_pressure_timeline.c` | Register pressure along an interval timeline |
| 279 | `279_assembler_symbol_address.c` | Symbol address assignment from instruction widths |
| 280 | `280_tac_identifier_validation.c` | Syntax check for simple three-address assignments |

## Run sample tests

```bash
bash tests/test_programs_271_280.sh
```

## Build an individual program

```bash
gcc -std=c11 -Wall -Wextra -pedantic programs/272_dfa_unreachable_pruning.c -o pruning
printf '3 0\n0 1\n1 1\n2 2\n' | ./pruning
```

These are bounded teaching examples, not complete compiler implementations. The floating-point recognizer supports only a small decimal syntax. The FIRST-set program assumes no epsilon productions. The LR stack simulator does not consult an LR parsing table. The expression-sharing example assumes pure, unchanged operands. The scripts provide representative smoke tests, not exhaustive validation. The C/C++ CI workflow remains removed.
