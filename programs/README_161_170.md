# Compiler Design Programs 161–170

Ten additional standalone C11 exercises for compiler construction.

| No. | Program | Concept |
|---|---|---|
| 161 | Lexer state machine | Tokenize simplified identifiers, integers, punctuation |
| 162 | Unit-production closure | Warshall closure of grammar nonterminal dependencies |
| 163 | CFG post-dominators | Fixed-point data-flow on single-exit graphs |
| 164 | DFA transition coverage | Count distinct edges visited by input |
| 165 | Lexical scope lookup | Resolve a symbol in nested lexical scopes |
| 166 | Array address calculation | Row-major offsets for 2D arrays |
| 167 | Register spill estimate | Peak excess live ranges over register budget |
| 168 | CFG critical edges | Detect edges requiring splitting |
| 169 | TAC code generation | Translate a limited TAC expression to pseudo instructions |
| 170 | Stack bytecode trace | Observe operand stack depth and result |

## Build and test

```bash
gcc -std=c11 -Wall -Wextra -pedantic programs/168_cfg_critical_edge.c -o critical
printf '4 4\n0 1\n0 2\n1 3\n0 3\n' | ./critical
bash tests/test_programs_161_170.sh
```

These programs are educational and intentionally bounded. Program 163 assumes all CFG nodes reach the selected exit. Program 167 estimates simultaneous spills, not optimal register allocation. Overflow handling and full language parsing are outside scope. The ten tests are sample checks, not exhaustive validation. The C/C++ CI workflow stays removed.
