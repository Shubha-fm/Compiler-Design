# Compiler Design C programs 311–315

Five new C11 exercises.

| No. | Program | Concept |
|---|---|---|
| 311 | [Comment-aware lexer counts](311_lexer_line_comment_tokens.c) | Token counting with `//` line-comment handling |
| 312 | [Dot/star regex matcher](312_regex_dot_star_match.c) | Dynamic-programming matching with `.` and `*` |
| 313 | [CFG topological order](313_cfg_topological_order.c) | Kahn's algorithm and cycle detection |
| 314 | [IR strength reduction](314_ir_strength_reduction.c) | Replace power-of-two multiplication with bit shifts |
| 315 | [Small LL(1) parse table](315_ll1_first_follow_table.c) | Lookahead-driven selection for a sample grammar |

Run the checks:

```bash
bash tests/test_programs_311_315.sh
```

Example:

```bash
gcc -std=c11 -Wall -Wextra -pedantic programs/312_regex_dot_star_match.c -o regex
echo 'a*b aaab' | ./regex
```

**Limits:** Program 311 is a simplified tokenizer, not a full C lexer. Program 312 supports only single characters, `.` and `*`; input `#` represents empty text. Program 313 assumes a bounded directed graph. Program 314 operates on unsigned multipliers and does not prove transformations correct for every signed arithmetic model. Program 315 illustrates one fixed grammar, not an arbitrary LL(1) table generator. Samples are not exhaustive.

The C/C++ CI workflow remains removed.
