# Compiler Design Programs 221–230

Ten standalone C11 teaching programs for lexical analysis, automata, grammar recognition, parsing, and compiler optimization.

| No. | Program | Topic |
|---|---|---|
| 221 | `221_dfa_intersection.c` | Simultaneous execution of two DFAs to recognize intersection |
| 222 | `222_nfa_subset_move.c` | NFA subset transition using bitmasks |
| 223 | `223_cyk_membership.c` | CYK parsing for nonempty words under a CNF grammar |
| 224 | `224_expression_precedence_parser.c` | Recursive-descent evaluation with operator precedence |
| 225 | `225_cfg_articulation_points.c` | Articulation points of the undirected CFG representation |
| 226 | `226_live_variables_fixedpoint.c` | Backward live-variable data-flow analysis |
| 227 | `227_ir_constant_folding.c` | Constant folding for simple integer TAC |
| 228 | `228_register_graph_coloring.c` | Greedy interference-graph register coloring |
| 229 | `229_symbol_table_hash_lookup.c` | Hash-table-backed symbol lookup |
| 230 | `230_bytecode_control_flow_validator.c` | Jump-target bounds checking in bytecode |

## Run tests locally

```bash
bash tests/test_programs_221_230.sh
```

## Run one example

```bash
gcc -std=c11 -Wall -Wextra -pedantic programs/224_expression_precedence_parser.c -o expression
echo '2+3*(4+1)' | ./expression
```

These programs have intentionally limited input formats. The arithmetic examples do not detect integer overflow. Program 225 uses an undirected graph, not directed strong articulation points. Program 228 uses a greedy heuristic and does not guarantee the minimum register count. The tests cover representative cases rather than exhaustive behavior.

No C/C++ GitHub Actions workflow is created.
