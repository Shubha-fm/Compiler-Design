# Compiler Design Programs 296–300

Five new C11 programs complement the existing compiler-design collection.

| No. | Source | Concept |
|---|---|---|
| 296 | `296_lexer_token_frequency.c` | Lexical token category counting |
| 297 | `297_regex_thompson_nfa.c` | Thompson epsilon-NFA construction for postfix regular expressions |
| 298 | `298_cfg_strong_components.c` | Strongly connected components with Kosaraju's algorithm |
| 299 | `299_grammar_first_follow.c` | Fixed-point FIRST, FOLLOW, and nullable computation |
| 300 | `300_stack_bytecode_vm.c` | A small executable stack-based virtual machine |

## Build and test

```bash
bash tests/test_programs_296_300.sh

gcc -std=c11 -Wall -Wextra -pedantic programs/300_stack_bytecode_vm.c -o vm
printf '5\nPUSH 7\nPUSH 5\nADD\nPRINT\nHALT\n' | ./vm
```

**Limitations:** Program 296 is an illustrative lexer and does not handle full C syntax. Program 297 expects postfix expressions with literals `a-z`, `#` (epsilon), `.` (concatenation), `|` (alternation), and `*` (repetition), and prints the NFA rather than simulating it. Program 298 accepts a bounded graph of 40 vertices. Program 299 supports uppercase one-character nonterminals, lowercase one-character terminals, `#` as epsilon, and assumes start symbol `S`. Program 300 uses bounded integer stacks and does not check arithmetic overflow or include jumps.

The script performs ten representative checks, but execution on a local machine is required to confirm results. The C/C++ CI workflow is not recreated.
