# Compiler Design Programs 281–290

Ten standalone C11 teaching programs covering lexical analysis, automata, grammars, parsing, control flow, SSA, intermediate code, and register allocation.

| No. | File | Topic |
|---|---|---|
| 281 | `281_lexer_hex_literal.c` | Hexadecimal integer literal recognition |
| 282 | `282_dfa_binary_word_trace.c` | Trace DFA states while reading a binary word |
| 283 | `283_grammar_indirect_left_recursion.c` | Left recursion via first-symbol dependency closure |
| 284 | `284_operator_precedence_table.c` | Table of precedence relations for arithmetic operators |
| 285 | `285_cfg_reverse_reachability.c` | CFG blocks that can reach a chosen exit |
| 286 | `286_ssa_phi_predecessor_listing.c` | Phi argument templates from block predecessors |
| 287 | `287_ir_constant_branch_elimination.c` | Fold constant conditional branches |
| 288 | `288_register_interference_edges.c` | Interference edges from half-open live intervals |
| 289 | `289_three_address_quadruples.c` | Three-address expressions as quadruples |
| 290 | `290_lr_reduce_goto_transition.c` | Illustrate LR reduction and GOTO-stack push |

## Run the sample checks

```bash
bash tests/test_programs_281_290.sh
```

## Compile a single example

```bash
gcc -std=c11 -Wall -Wextra -pedantic programs/282_dfa_binary_word_trace.c -o dfa_trace
printf '2 0\n0 1\n1 0\n101\n' | ./dfa_trace
```

These are educational examples, not full compiler implementations. The grammar recursion checker assumes no nullable leading nonterminal sequence. The precedence table does not represent a full operator-precedence grammar. The SSA phi generator lists symbolic incoming arguments without validating SSA dominance. The LR reduction example demonstrates stack manipulation, not an LR parsing-table implementation. Sample checks cover basic inputs and are not exhaustive. The C/C++ CI workflow remains removed.
