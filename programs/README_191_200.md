# Compiler Design Programs 191–200

Ten standalone C11 programs covering lexical, automata, grammar, parser, and optimization exercises.

| No. | File | Topic |
|---|---|---|
| 191 | `191_lexer_keyword_boundary.c` | Exact keyword versus identifier recognition |
| 192 | `192_regex_shunting_yard.c` | Infix to postfix regex conversion with explicit concatenation |
| 193 | `193_nfa_move_set.c` | NFA transition MOVE over a state subset |
| 194 | `194_grammar_follow_trailer.c` | FOLLOW contribution from a nullable suffix |
| 195 | `195_cfg_dominance_frontier.c` | Dominance frontier of a reachable CFG |
| 196 | `196_dataflow_reaching_definitions.c` | Reaching definitions fixed-point analysis |
| 197 | `197_ir_strength_reduction.c` | Replace power-of-two multiplication with a shift |
| 198 | `198_stack_effect_analyzer.c` | Stack effects of simple instructions |
| 199 | `199_basic_block_successor_matrix.c` | Control-flow adjacency matrix |
| 200 | `200_lr_shift_reduce_trace.c` | Shift/reduce trace for a restricted grammar |

## Run the tests

```bash
bash tests/test_programs_191_200.sh
```

## Compile a program

```bash
gcc -std=c11 -Wall -Wextra -pedantic programs/196_dataflow_reaching_definitions.c -o reaching
printf '2 1\n0 1\n1 0\n2 0\n' | ./reaching
```

**Scope:** These are teaching examples, not full C language implementations. Program 195 requires every CFG block to be reachable from node 0. Program 197 assumes nonnegative operands and ignores overflow. Program 200 recognizes only a restricted grammar. Tests are smoke checks, not exhaustive verification. No C/C++ GitHub Actions workflow is installed.
